01

结论与审阅边界

建议做一个只管“连接、帧、生命周期、可恢复性”的薄内核，不把 PLC 协议、业务命令、DI 容器、消息总线和磁盘队列塞进核心。协议差异通过启动时静态注册的工厂委托注入；运行时只按配置创建已编译类型的新实例。

一句话架构

Driver 是唯一资源所有者；每个逻辑设备有一个 Supervisor；每条物理连接有一个不可变 ConnectionContext 和一套全新协议栈；配置变更走单写者事务；NativeAOT 下只允许显式工厂创建，不允许运行时发现类型。

这样可以把“轻量”落到可检验的约束上：核心只有一个程序集，不依赖第三方包，不启反射扫描，不创建设备专用常驻线程，所有队列和帧长度有上限，停机时可等待全部受管任务退出。

02

现有实现调研与取舍

调研目标不是选一个现成库直接依赖，而是抽取工业 TCP 场景已经被验证的边界。尤其要区分“借鉴架构思路”与“把第三方程序集放进 NativeAOT 依赖树”：后者必须实测，本文不作未验证的兼容承诺。

来源已核实的做法 / 约束本设计借鉴本设计不采用
Microsoft · Native AOT deployment 无 JIT、按 RID 发布、必须裁剪；禁止 Assembly.LoadFile 与 Reflection.Emit；IsAotCompatible 开启裁剪/AOT/单文件分析器；建议库至少包含 net8.0。 把 AOT 作为发布期与 CI 的硬门禁；库声明 IsAotCompatible，应用设置 PublishAot。 不用运行时插件加载、程序集扫描、动态代理和运行时生成泛型代码。
Microsoft · STJ source generation JsonSerializerContext / JsonTypeInfo<T> 重载；object 运行时类型需显式登记；可关闭反射默认；NativeAOT 不支持非泛型 JsonStringEnumConverter。 全部配置 DTO 静态登记；扩展参数用 JsonElement 固定键校验；关闭反射式 JSON。 不用 Deserialize(string, Type)、开放式多态和 Dictionary<string, object>。
Microsoft · Socket 异步方法可传 CancellationToken；可取消重载返回 ValueTask；发送必须循环写完整；Connected 只反映最近一次 I/O；接收 0 字节表示对端优雅关闭。 连接、读、写、握手、退避都有取消令牌与超时；写完整帧后释放锁；链路活性不依赖 Connected。 不把一次 Send 成功解释为设备收到或执行。
TouchSocket 4.3 · 数据适配器 TCP 是流式单线程，存在粘包/半包；固定包头、固定长度、终止符、字符区间四类分包；适配器必须用工厂委托按终端新建；有 MaxPackageSize、缓存超时。 IFrameCodec 每条连接新建；限制最大帧；半帧缓存超时后丢弃并拆链；编解码与业务分离。 不照搬整套插件/RPC/协议组件，不共享有状态 decoder 单例。
TouchSocket 3.1 · 断线重连
4.3 · 活性检查		 旧版重连文档明示：首次连接需已成功、主动 Close 不触发、拔网线需等 TCP 保活到期；默认只查 Online，可用自定义检查发心跳。4.3 的 CheckClear 定时检查收发活跃度，并提示 OS 定时器会有延迟。 把“主动停止”与“被动断开”拆开；用应用层 Ping/Pong 判死；冷启动失败不阻塞 StartAsync；定时器用注入时钟测试。 不以 3.1 的旧 API 行为推断 4.3；不以 TCP keepalive 或 Online 作为 Ready 判据。
TouchSocket 4.3 · WaitingClient 默认不筛选响应，可能拿到过期响应；高可靠场景建议在协议中加入 requestId 做请求与响应关联；简单等待机制存在锁竞争与接收器生命周期问题。 单读泵 + (Epoch, RequestId) 待响应表；默认单在途；未知/重复/迟到帧进入事件通道。 不用“下一个响应就是本次响应”的队列，也不在接收回调内同步等待响应。
SuperSocket 2.0 · 基本概念 用 Package Type 表示业务包，用 PipelineFilter 把字节流解码成包；HostBuilder 组合包类型与过滤器。 借鉴“传输字节流 / 帧 / 业务语义”三层分离；Codec 工厂与业务 API 独立。 不引入完整 Command、泛型 PipelineFilter 体系和 HostBuilder 作为核心依赖。
HslCommunication README 展示工业 PLC 读写用 OperateResult<T> 显式表达成功、内容与失败信息，并区分短连接与 SetPersistentConnection() 长连接；README 标明商业高级功能授权要求。 借鉴“显式结果类型”和长连接生命周期的语义价值；命令返回可区分 Ack 与执行结果。 不复制代码，不内置品牌 PLC 协议，不将其作为 NativeAOT 依赖；兼容性未实测。

调研结论。工业现场的问题不是“怎样调用 ConnectAsync”，而是半开连接、旧响应、写命令结果未知、设备重启后身份变化、配置热变更和发布期裁剪。现有库的架构价值集中在适配器、活性检查和显式结果；本设计把这些作为核心语义，把协议族、RPC、业务框架留在外面。

03

目标、非目标与硬约束

目标

  • 同时管理两类链路：主动连接设备侧 TCP Server；自身监听并接受设备侧 TCP Client。
  • 运行时新增、更新、删除设备与监听端点，且变更失败可回滚。
  • 断线后按指数退避与抖动重连，支持多端点、DNS 重解析、身份校验与端点冷却。
  • 提供可插拔帧层：固定长度、长度前缀、终止符以及应用自定义 framer。
  • 可测试的超时、心跳、故障注入、取消和优雅停机。
  • 核心可被 .NET 8+ / .NET 10 的 NativeAOT 应用引用，发布时零 IL 裁剪/AOT 警告。

首版非目标

  • 不实现 Modbus、S7、MC、FINS、SECS 等具体工业协议。
  • 不提供运行时插件目录、动态程序集加载或按字符串反射创建类型。
  • 不做 TLS、串口、UDP、WebSocket、HTTP、RPC。
  • 不做磁盘持久化命令队列、消息总线、集群选主、Web 管理台。
  • 不保证配置更新零中断；默认 break-before-make。
  • 不自动重放写命令，也不替业务决定幂等策略。

硬约束

编号约束可检验方式
C1LiteDriver.Core 零 PackageReference，只用 BCL。dotnet pack 后检查 nuspec 各 TFM 依赖组为空。
C2多目标 net8.0;net10.0；IsAotCompatible=true；警告即错误。双 TFM Release build + AOT smoke publish。
C3配置 JSON 全走源生成，关闭反射式序列化。负例测试：反射式重载抛异常；publish 无 IL2026 / IL3050。

总体架构与包边界

核心按“公开 API → 编排 → 会话 → 协议 → 传输”单向依赖。时间源、观测者、限制和传输工厂由构造参数注入，不引入服务定位器。所有可变状态归 ConnectionContext 或 DeviceLease 所有。

图 1 · 分层架构。右侧边界是产品契约：运行时可以动态管理设备和端点，但不能动态产生新的本机代码。

包边界

程序集内容依赖AOT 责任
LiteDriver.CoreAPI、状态机、Socket 传输、帧层接口、显式注册表、源生成配置 DTO、观测抽象、默认 framer 实现。仅 BCL，零 NuGet。IsAotCompatible、零 IL 警告、静态可达。

LiteDriver.Logging

命名说明：LiteDriver 是随工作区名称拟定的暂定名，尚未检查 NuGet 包名占用、商标或组织命名规范。此项列入第 12 节待确认。

两种链路共用一个窄通道抽象

图 2 · 设备拓扑。出站与入站只在 IFrameChannel 汇合；拨号、监听和重连策略不会泄漏到 DeviceHandle。

为什么不是胖 Connection。若把 Connect()、Listen()、Reconnect() 和协议方法塞进同一个类，服务端会话会暴露无意义的拨号 API，客户端配置会带监听端口，重连后还容易复用旧状态。这里只共用收发、状态、标识和关闭；连接来源由 Supervisor 决定。

05

AOT 下的动态创建

本设计把两个常被混用的概念明确拆开：

运行时动态配置：支持

  • 从配置数据新增设备、监听器、端点。
  • 更新已有设备的重试、心跳、端点、协议参数。
  • 删除设备并等待所有任务、socket、缓冲退出。
  • 根据已注册 kindId 创建一批已编译类型的新实例。

运行时动态代码：禁止

  • 加载新 DLL 或扫描目录发现驱动。
  • 按字符串 Type.GetType 或 Activator.CreateInstance(Type)。
  • Reflection.Emit、Expression.Compile、运行时 MakeGenericType。
  • 反射式 JSON 多态反序列化。

静态工厂注册表

Builder.RegisterKind 把字符串键绑定到 Func<KindRegistrationContext, IDeviceKind>。StartAsync 冻结注册表；之后 ApplyAsync 只能引用已注册键。IDeviceKind 不保存 Type，只在每次建立物理连接时调用 CreateProtocol 生成全新的 decoder、correlator、initializer、heartbeat 与 identity policy。

// 启动期：所有分支在编译产物中静态可达
var driver = new LiteDriverBuilder()
    .RegisterKind("length-prefix-v1", static _ => new LengthPrefixKind())
    .RegisterKind("line-device-v1",   static _ => new LineDeviceKind())
    .UseTimeProvider(TimeProvider.System)
    .UseObserver(observer)
    .Build();

// 运行期：只创建已编译类型的新实例；kindId 不是类型名
await driver.ApplyAsync(config, ct);

public interface IDeviceKind
{
    ISessionProtocol CreateProtocol(in ProtocolContext context);
}

public interface ISessionProtocol
{
    IFrameDecoder Decoder { get; }          // 每条物理连接新实例
    IFrameEncoder Encoder { get; }
    IRequestCorrelator Correlator { get; }  // 可返回 NoCorrelationPolicy
    ISessionInitializer Initializer { get; }
    IHeartbeatPolicy Heartbeat { get; }
    IDeviceIdentityPolicy Identity { get; }
    CommandPolicy Commands { get; }
}

ProtocolContext 携带稳定的 DeviceId、Direction、冻结后的 DriverLimits 和已 Clone() 的 JsonElement KindSettings。设备种类实现负责校验自己的固定扩展键，例如长度字段字节序、最大帧长、unit id；校验失败在配置 Stage 阶段返回，不在首次收包时才暴露。

// 禁止：

// JsonSerializer.Deserialize<T>(json);   // 依赖反射默认值的重载

核心与 smoke app 都设 JsonSerializerIsReflectionEnabledByDefault=false。枚举在 net8.0 下使用泛型 JsonStringEnumConverter<TEnum>；不使用 NativeAOT 不支持的非泛型转换器。配置中的可变集合在 ValidateAndFreeze() 中克隆为内部只读快照，避免业务持有引用后原地修改。

可达性不是标签保证的。IsAotCompatible=true 只启用分析器，不能证明每个工厂分支被保留。AOT smoke app 必须静态执行每个注册 kind 的创建路径，并在原生二进制里做一次真实 loopback 收发；否则未被静态引用的类型或值类型泛型实例化可能在发布后被裁掉。

06

生命周期与重连状态机

核心拆分：RunState 表示 Driver / DeviceLease 的对象生命周期，LinkState 表示某条链路的可用性。主动 Stop 与被动断线绝不走同一条恢复分支；StartAsync 只负责启动唯一 Supervisor，不等待无限重连成功。

图 3 · 两套正交状态。冷启动失败、被动断线、认证拒绝和主动停止分别有明确出口。

图中转移标记

  • A：Connecting 遇到拒绝、超时、DNS 失败，进入 RetryWait。
  • B：Handshaking 遇到身份或协议拒绝，进入 Faulted。
  • C：任意链路状态收到主动 Stop，进入 Stopped。
  • D：Reconnecting 按退避与抖动等待，生成新 attemptGeneration、重解析 DNS，进入 RetryWait。
  • E：RetryWait 到期后重试下一端点，回到 Resolving。

图中刻意不画的事

不画 Ready → Connecting 的直接跳线。链路失效必须先关闭当前 epoch、作废 pending、丢弃半帧，再由唯一 Supervisor 进入重连；该过程在下方时序图展开。

不把服务端 accept 循环塞进客户端状态机；服务端会话有独立的 SessionContext 与容量上限。

重连规则

阶段规则防错点
尝试代每轮生成 attemptGeneration，重新读取不可变端点快照并重解析 DNS；单地址拨号有独立超时。旧轮次的迟到成功不得发布为 current；不允许两个并发拨号同时写同一逻辑设备。
端点选择有序端点 + 每端点冷却；瞬时错误切下一个端点；容量/最大会话拒绝按较长冷却处理。日志同时记录主机名、解析 IP、endpointId、attemptGeneration，避免只看字符串误判设备。
退避指数退避 + 抖动 + 上限；由 TimeProvider 驱动，不散落 Task.Delay。认证错误不进入无限 hammering；测试可快进时间而不是真的等待。
建连后依次执行应用握手、协议版本、认证、设备 ID / bootId / sessionNonce 校验、首个合法帧；成功后才置 Ready。TCP 连上不等于设备可用；DNS 换到另一台同协议设备时必须拒绝或开新代。
拆链时CAS 关闭旧 ctx → 取消 per-link CTS → shutdown/close socket → 丢弃半帧 → 排空 pending → 递增 epoch。所有回调捕获 ctx，投递前检查 ReferenceEquals(current, ctx) 与 epoch；旧帧记 StaleEpoch 后丢弃。
停止时先写 RunState=Stopping，取消生命周期 CTS，再关闭 socket；等待读泵、写泵、心跳和 accept 循环退出。旧 socket 的断开回调晚到也不触发重连；StopAsync 幂等，超时后强制 abort 并记录。

有界写队列单写者，循环写完整个帧
SocketConnect / Accept 共用 IFrameChannel
单读泵ArrayPool 缓冲 + 半帧累积
Framer每连接独立状态，最大帧 / 缓存超时
Correlator匹配 / 重复 / 迟到 / 推送
投递TCS 或 IDriverObserver

图 4 · 数据路径。写侧只串行化“完整帧写入”，不把等待响应的时间占住写锁；读侧只有一个消费者解析粘包/半包。

帧层契约

  • IFrameDecoder 每条连接新建，内部保存未完成半帧；不得共享。
  • IFrameEncoder 可无状态；输出必须是一个完整可写帧。
  • 回调中的 ReadOnlyMemory<byte> 是借用视图，只在回调期间有效；需要跨调用保存必须复制。
  • 超过 MaxFrameSize、半帧缓存超时、非法长度字段一律关闭当前链路并发事件，不尝试在污染字节流上继续猜边界。
  • 内置三种工厂：固定长度、长度前缀、终止符；自定义 framer 由 IDeviceKind 提供。

请求关联

  • 并发 Exchange 要求协议帧带 requestId 且响应原样回带。
  • 默认 MaxInFlight=1；只有协议明确支持流水线且 ID 空间足够，才允许调大。
  • 16 位事务 ID 需限制窗口、超时后置入 tombstone，保留 LateResponseWindow 后再复用。
  • 重复、未知、旧 epoch 响应进入事件通道；绝不完成另一个等待者。
  • 协议完全不能带 ID 时，强制单在途串行并禁止并发 Exchange。

命令结果必须可区分

Disposition含义库是否自动重试
NotSent可确认整帧零字节未写入，例如校验失败、背压拒绝、未 Ready、取消发生在入队前。否；调用方可决定是否重新发起。
SentOutcomeUnknown整帧已交给内核但无匹配应用 ACK，或发生超时、拆链、设备重启、部分写出后异常。否。禁止自动重放。
Rejected收到同 epoch、同 requestId 的应用层否定应答。否。
Executed收到匹配的应用层执行 ACK；如业务要求，应再读回状态或版本。否。
Canceled调用方取消且可确认尚未完整写出；若已部分写出则升级为 Unknown。否。
BackpressureRejected写队列或在途表达到上限，命令没有进入发送路径。否；返回明确错误码与当前队列深度。

关键安全边界。SendAsync 成功只表示字节进入内核缓冲；TCP ACK、设备应用 ACK、设备实际执行是三个不同事实。写命令可能在 ACK 丢失前已执行，也可能根本没执行。重连、心跳超时和端点切换后自动重发同一帧，可能造成双次动作。库只报告 SentOutcomeUnknown；业务若需重试，应提供设备侧稳定的 commandId 幂等键或先状态读回。

活性检查

应用层心跳

Ping 携带 epoch + 单调 seq；Pong 必须匹配当前 epoch 与 seq。连续 N 次未回或静默超上限即 LinkDead。优先使用协议 Ping；没有 Ping 时用只读状态寄存器，绝不用写命令当心跳。

TCP keepalive

仅作内核最终回收和极长故障兜底。平台支持的 TCP_KEEPIDLE/INTVL/CNT 可配置；它只能证明对端内核可能还活着，不能证明 PLC 应用、协议会话或设备身份仍有效。

判死预算

建议初值：心跳 5 s、连续 3 次未回、静默上限 20 s、connect 3 s、handshake 3 s、退避 0.5 s → 30 s、抖动 20%。这些是待压测/现场校准的建议值，不是已验证事实。

身份与设备重启

Ready 前的应用握手必须核对协议版本、认证结果、设备 ID，以及可获得的 bootId 或 sessionNonce。若设备不暴露 bootId，则用握手 nonce + 状态/序列号读回；无法区分重启时，所有在途写只能标记 Unknown。DNS 指向新设备、bootId 变化或 sessionNonce 变化时，创建新的 epoch，清空缓存与订阅，重新读回设备状态，旧排队写不迁移。

不可破坏的不变量

  • 同一个 socket 任意时刻只有一个写循环；完整帧写完才释放写锁。
  • 同一个 socket 任意时刻只有一个读泵；decoder 不跨连接复用。
  • 所有回调携带 (DeviceId, Generation, ConnectionId, Epoch)，旧代一律丢弃。
  • 无界内存增长不存在：写队列、pending 表、读缓冲、帧长、监听会话数均有上限。
  • 主动 Stop 产生的关闭不会触发重连；旧回调不会让已删除设备复活。
  • 未识别的入站设备默认拒绝；认证失败不置 Ready。
  • 观察者、codec、initializer 抛出的异常有明确记录并关闭当前连接；禁止空 catch 吞掉故障。
  • 所有 fire-and-forget 任务都登记到所属 lease 的 TaskGroup，StopAsync 等待其退出。

配置与事务化变更

所有配置变更串行进入单写者队列。ValidateAndFreeze() 先生成不可变快照；Generation 标识逻辑设备的一代配置。回调必须携带 (DeviceId, Generation)，旧代回调在提交后全部失效。

1ValidateID 唯一、kind 已注册、host/port、时间范围、帧长、队列、端口冲突、每 kind 扩展键。
2Freeze克隆数组与 JsonElement；生成只读快照与每个设备的下一代 Generation。
3Stage为新增 listener 预绑定端口；为变更项创建 lease；失败即释放本轮新建资源。
4Commit一次性原子替换当前快照，发布新 revision；此后路由只看新 generation。
5Retire取消旧 CTS、停 accept / 读写 / 心跳、排空 pending、等待 quiescence、释放端口与缓冲。

图 5 · Apply 事务。Stage 任一失败保持旧快照；提交后的清理有超时与强制 abort 兜底。

更新语义：默认 break-before-make

同一 DeviceId + KindId + bindingKey 且仅心跳/退避等无副作用参数变化时，调用 UpdateSettings 原地更新不可变设置。端点、协议参数或监听端口变化，则停用旧 generation 并创建新 generation。

首版默认不允许同一逻辑设备同时存在两条活动物理连接，避免工业设备单会话限制和双写。若评审要求零中断，需要设备明确支持双会话，并另做 make-before-break 切换协议。

删除语义：等待 quiescence

RemoveDeviceAsync / RemoveListenerAsync 返回前，必须完成取消、关闭、pending 收束和任务退出；返回后才允许同 ID 再次 Add。端口删除后 smoke test 应验证不可连接。

监听端点的端口冲突在 Stage 暴露为明确的 PortConflict，回滚全部新建 listener，旧快照继续服务。

配置输入边界

核心公开的是 POCO 与 ApplyAsync；可选的 source-gen JSON 读取器只负责把固定契约解析成 POCO，然后调用同一个 ValidateAndFreeze。核心不监视文件、不访问数据库、不订阅配置中心；热更新来源属于宿主应用。Hosting 适配层若引入 IConfiguration，不得复制一套校验规则。

可观测性与资源上限

结构化事件

IDriverObserver.OnEvent(in DriverEvent e) 是核心唯一观测出口。事件字段固定：EventId、时间、DeviceId、ListenerId、Generation、ConnectionId、Epoch、Direction、Kind、错误码、端点、耗时。生产默认 Noop。

可选 Logging 包把事件映射到 [LoggerMessage]；不在 Core 依赖 ILogger，也不反射读取匿名对象。

必要指标

connect attempts / successes / failures、handshake failures、reconnects、ready duration、heartbeat timeouts、stale frames、unknown responses、pending timeouts、send unknown、backpressure drops、apply rollback、quiescence timeouts。计数器用 Interlocked，快照读取无锁。

资源默认上限策略超限行为
写队列每连接有界 Channel，建议初值 128；入队可带超时。BackpressureRejected；不阻塞无限业务线程，不落盘。
在途请求默认 MaxInFlight=1；有 requestId 且协议允许时可调大。拒绝新请求或按策略等待有界时间。
帧长 / 半帧缓存MaxFrameSize 建议初值 1 MiB；缓存超时建议 1 s，按协议校准。关闭当前链路、丢弃缓存、发 FrameLimitExceeded 或 FrameCacheTimeout。
读缓冲ArrayPool<byte> 租用固定大小；每连接独立，finally 归还。不随粘包长度无界扩张；异常路径也归还。
监听会话每 listener MaxSessions；全局可加总上限。显式拒绝帧或受控关闭，说明容量原因。
停机全局 StopTimeout；先 graceful shutdown，再 abort。超时强制关闭并记录未完成 lease，不无限等待。

故障注入接口：IChaosPolicy 只在测试构建注入，生产默认 Null，不能由普通配置静默开启。脚本按 seed + step 编号可重放：拨号拒绝、accept 即断、半帧、延迟/乱序响应、重复响应、写超时、握手失败、设备重启、DNS 指向不同身份。

编号默认选择为何需要你确认若改变的影响
Q1项目暂名 LiteDriver，核心仅 net8.0;net10.0 双目标。包名、命名空间、最低 TFM 属于长期兼容契约；尚未检查占用。若需 netstandard2.0 或 .NET Framework，AOT 分析器与 API 形态需重新设计。
Q2首版仅 TCP 明文；TLS、串口、UDP、WebSocket 和具体 PLC 协议全部在核心之外。工业设备协议与链路类型决定 ITransportFactory 和 IDeviceKind 的边界。若首版必须支持 TLS / 串口，需要增加传输装饰层及对应 AOT 与故障注入测试。
Q3动态创建采用启动期冻结的显式 kindId → factory 注册表；新增协议需重新编译发布。这与“运行时装插件”是完全不同的产品能力。若必须运行时加载新驱动，NativeAOT 目标需放弃或改为独立进程外插件。
Q4配置更新默认 break-before-make；同一逻辑设备不并发持有两条活动连接。零中断更新要求设备支持双会话，且需明确切换点。若要求零中断，需另设计 make-before-break、双会话身份校验与切换失败回滚。
Q5并发请求要求协议带 requestId；无 ID 时强制单在途串行。需要确认实际设备/网关帧格式能否添加或已有事务 ID。若不能携带 ID，吞吐受限；若可以，需确定 ID 位宽、回绕与重复抑制策略。
Q6写命令断线/超时后绝不自动重放；只返回 SentOutcomeUnknown。业务侧是否有幂等 commandId、状态读回或人工对账流程。若要求库内自动重试，必须定义设备侧幂等键与对账协议，否则有双次动作风险。
Q7入站设备默认拒绝未知身份；每个监听端口绑定一个 kindId。需要确认现场是否有一个端口混接多种设备、以及设备身份来自哪里。若混接，需要协议协商器与多 kind 路由；会增加握手状态机和测试组合。
Q8核心只接受 POCO；可选 source-gen JSON 读取器；不内置文件监听/配置中心。配置来源可能是文件、数据库、MQTT、上位机 API 或 Web 配置台。若需要核心直接热加载，需确定源、鉴权、失败与回滚语义，但不应引入反射绑定。
Q9AOT 矩阵建议 linux-x64/arm64 · win-x64 · osx-arm64，在对应原生 runner 发布。实际部署平台、CI 预算和最低 glibc / Windows / macOS 版本未确认。减少平台可缩短 CI；增加平台需补原生工具链、符号文件与现场 smoke。
